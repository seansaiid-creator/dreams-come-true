### [해결] AdFit이 되살아나 라이브에 노출됨 — 내가 만든 사고
**증상**: 09-02 AdFit을 제거했는데(`674043b`), 이후 UI/UX 재점검에서 **141개 파일에 다시 살아있는 것**이 발견됐다. 라이브에도 나가 있었다.
**원인**: `docs:` 커밋(`25b14c8`)을 하면서 `git add -A`로 워킹 트리 전체를 담았고, 그 안에 옛 버전 파일이 섞여 있었다. **커밋 전 `git diff --stat`을 확인하지 않은 내 잘못.**
**처리**: 재제거 후 배포 + `health-check.mjs`에 **AdFit 재삽입 감시**와 **구 도메인 잔존 감시** 추가 → 재발 시 월요일 헬스체크가 잡는다. 발행 워크플로의 `verify-publish.mjs`에도 같은 검사를 넣어 자동 발행 경로로는 재발 불가.
**교훈**: 커밋 전 **변경 파일 수를 반드시 눈으로 확인한다.**

### [해결] 구글이 사이트를 크롤링하고도 색인하지 않음
**증상**: 92일간 구글 유입 **0회**. GSC에서 홈이 "크롤링됨 – 현재 색인이 생성되지 않음", 개별 페이지는 "아직 알려지지 않은 URL". sitemap 마지막 읽기가 **5개월 전(4/10)**, 발견 페이지 35개.
**1차 가설(부분적으로만 맞음)**: canonical 404 19건 때문에 구글이 깨진 사이트로 판단 → 수리 후 sitemap 재제출. **오늘 날짜로 재읽기 성공, 145개 인식**. 하지만 색인은 여전히 거부.
**2차 가설(적중)**: `*.vercel.app`은 누구나 쓰는 **무료 공유 서브도메인**이라 구글이 신뢰도를 낮게 매긴다. 네이버는 이런 구분을 덜 해서 네이버에서만 잘 잡히던 패턴이 정확히 설명된다.
**검증**: 도메인 이전 직후 `suksuki.com` 홈이 **"URL이 Google에 등록되어 있음 / 색인 생성됨"** 으로 바뀜. 같은 콘텐츠인데 도메인만 달라졌다. **가설 확정.**
**남은 것**: 개별 페이지 색인이 쌓이는 중. 09-06 확인 예정.

### [해결] CTA 착지의 61%가 엉뚱한 해몽
**증상**: 사용자가 8,000자짜리 "가방 잃어버리는 꿈"을 읽고 버튼을 누르면 *"무언가를 잃어버리는 꿈은…"* 같은 일반론이 나왔다. **14개 분실 꿈이 전부 같은 문장·같은 등급**.
**원인**: 홈의 해몽 DB가 48개뿐인데 페이지는 139개. 매칭 실패 시 카테고리 폴백으로 떨어졌다.
**처리**: 각 페이지의 실제 해몽 본문·조언을 추출해 `dreams-db.js` 생성, CTA에 슬러그를 실어 정확히 조회. 길흉 등급은 사이트가 이미 손으로 정한 값을 우선 재사용.
**주의**: 신규 발행 시 재생성이 필요한데 **수동 단계를 남기면 언젠가 빠뜨린다** → 발행 워크플로에 자동 실행으로 넣음.

### [해결] 음력 변환 버그 2건 — KASI 대조가 아니었으면 놓쳤다
- **연도 귀속 오류**: `2010-12-22` → 음력 2009년으로 나옴(월·일은 맞음). 원인은 마지막 동지월(11월)의 연도를 `sy-1`로 일괄 계산한 것. 실제로는 그 달이 `sy`에 속한다 → 구성 시점에 연도를 명시적으로 부여하도록 수정
- **윤달 번호 규칙**: 2020년 **윤4월**을 윤5월로 표기. 윤달은 **직전 달 번호를 물려받는데** 다음 번호를 쓰고 있었다 → 수정
- 수정 후 KASI 41건 전항목 일치

### [해결] 사주 월주가 KASI와 3건 불일치 — 알고 보니 개념 차이
**증상**: KASI 대조에서 월주 3건이 달랐다.
**판정**: KASI가 주는 `LUNC_WLGN`(월건)은 **음력 달의 간지**이고, 사주 월주는 **절기 기준**이라 원래 다른 값이다. 절기 시각으로 우리 값이 맞음을 확인(1990-03-05 경칩 3/6 05:15 → 인월 등).
**처리**: 대조 항목에서 월건 제외하고 그 근거를 코드 주석에 남김. **불일치를 무조건 버그로 보지 않는다.**
